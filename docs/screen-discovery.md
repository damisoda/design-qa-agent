# 프로젝트에서 화면 찾아 연결하기

로컬 웹 화면 `/#/new`에서 프로젝트 폴더를 입력하면 화면 후보를 찾습니다. 검사할 화면을 체크하고 화면마다 Figma 프레임을 선택한 뒤 **검사 시작**을 누릅니다. Figma 플러그인으로 가져온 프레임과 기존 시안 목록을 모두 사용할 수 있습니다.

- 프로젝트의 `.dqa.json`에 등록된 화면이 있으면 그 진입 절차를 유지합니다.
- 설정이 없으면 HTML 페이지, React Router의 JSX/객체 경로, Vue Router의 직접 선언된 경로, Next/Nuxt 페이지 파일, Expo Router 화면 파일을 정적으로 읽습니다.
- `node_modules`, 빌드 결과, 테스트, 숨김 폴더, 심볼릭 링크는 탐색에서 제외합니다. 파일 수·크기·깊이에 한도가 있습니다.
- `/products/:id`와 `/products/[id]`는 실제 값으로 바꿔야 합니다. 예: `/products/123`.
- 계산되거나 다른 모듈에서 조합되는 경로, 로그인·클릭 이후 상태는 자동으로 확정하지 않습니다. 목록에 없는 주소는 화면에서 추가할 수 있습니다. 주소 추가만으로 인증 절차가 만들어지지는 않습니다.
- 파일 구조를 찾는 기능과 빌드 지원은 별개입니다. 현재 자동 빌드는 정적 HTML, Vite, CRA, Expo를 지원합니다. Next/Nuxt 경로를 찾았더라도 빌드 방식이 지원되지 않으면 검사를 시작하지 않습니다.

검사 시작 시 연결을 `dqa/state/screen-recipes`에 프로젝트의 실제 경로별로 저장합니다. 사용자 프로젝트에는 `.dqa.json`을 생성하거나 수정하지 않습니다. 같은 프로젝트를 다시 열면 선택한 화면, 실제 주소, Figma 연결을 복원합니다. 다른 프로젝트에서 저장한 자동 화면은 사용할 수 없습니다. 생성된 검사 절차는 주소마다 다른 ID를 사용하여 과거 실행의 시작 주소를 바꾸지 않습니다.

새 화면이 추가되면 **다시 찾기**를 누르세요. Figma 수정은 **이 시안 다시 가져오기**로 갱신합니다. 각 화면의 프레임 선택을 바꾸면 왼쪽에 그 프레임의 미리보기가 표시됩니다. **Figma 선택 자동 연결**을 켜둔 상태에서 Figma 앱의 파일·프레임을 바꾸면 선택 목록이 따라옵니다. 저장된 시안은 **가져오기**를 눌렀을 때만 바뀝니다. 자동 연결이 실패하면 **Figma 연결하기**로 다시 시도하세요. macOS 자동 실행에는 최초 플러그인 등록과 앱 제어 권한이 필요합니다.

검사와 수정은 모두 기존 Dify 워크플로를 거칩니다. 연결 API는 설정만 저장하며, 검사나 코드 수정을 직접 시작하지 않습니다. 모델 수정은 사본에서 수행하고 선택한 검사 화면들을 재검증합니다. 선택하지 않은 화면까지 검증한 것으로 표시하지 않습니다.

검증: `node --test dqa/test/screen-discovery.test.js dqa/test/import-selection.test.js dqa/test/dify.test.js dqa/test/repair-routing.test.js`

# P04 선행 연구 요약 — 디자인과 구현의 불일치 찾기

작성: 조대흠, 2026-10-06. 초록·요약 수준으로 정리했으며, 수치는 각 논문 원문으로 다시 확인해야 한다.

## 화면 한 장 비교는 이미 연구되었다

- **GVT** (Moran 외, ICSE 2018, arXiv 1802.04732)
  - 안드로이드 앱의 목업과 구현 화면을 받아 구성요소의 계층 구조를 짝짓고, 컴퓨터 비전으로 디자인 위반을 보고한다.
  - 심은 위반 기준 정밀도 98%, 재현율 96%를 보고했고, Huawei에서 산업 평가를 했다.
- **GUIPilot** (ISSTA 2025, github.com/code-philia/GUIPilot)
  - 모바일 디자인 목업과 구현의 화면 불일치와 화면 전환 불일치를 찾는다.
  - 화면을 위젯(위치·폭·높이·종류) 묶음으로 바꿔 정렬 문제로 풀고, 화면 전환은 비전-언어 모델로 동작을 추론한다.
  - 앱 80개, 목업 160개에서 화면 불일치 정밀도 99.8%, 재현율 98.6%를 보고했다.

이 두 연구는 디자인과 구현의 **화면 한 장**을 비교한다. 화면 크기를 바꾸거나 상태를 만들어 가며 생기는 결함, 원인 코드 추적은 다루지 않는다.

## AI가 디자인을 코드로 바꿀 때의 문제

- **Figma2Code** (ICLR 2026, arXiv 2604.13648, 데이터 xcodemind/Figma2Code)
  - Figma 커뮤니티 디자인(메타데이터·이미지·에셋) 213개로 디자인→코드 생성을 평가했다.
  - 상용 모델은 겉모습 유사도는 높지만, 절대 위치 사용 비율이 최대 31%(반응형 취약), 임의 값 사용 비율이 최대 49.97%(디자인 토큰 무시)였다.
  - 다듬기 에이전트(F2CAgent)의 개선 폭은 작았다.
- **Interaction2Code** (ASE 2025)
  - 웹페이지 127개, 상호작용 374개로 상호작용 생성을 평가했다.
  - 모델은 상호작용 생성이 약하고, 실패 유형 10가지를 보였다. 시각적으로 미묘한 상호작용에 특히 약했다.
- **DesignRepair** (ICSE 2025)
  - Material Design 지침을 RAG로 써서 생성된 프런트엔드의 디자인 품질(접근성·사용성)을 고친다.
  - 디자인 원본과의 비교가 아니라 지침 준수를 본다.

## 현업에서 보고된 문제 (Figma MCP 사용 후기)

- 코딩 에이전트가 Figma 컴포넌트와 코드 컴포넌트의 대응을 몰라 새 컴포넌트를 만든다.
- 디자인 토큰 대신 값을 하드코딩한다.
- 큰 페이지의 디자인 데이터가 도구 응답 한도에서 잘려 들어간다.

## 이 프로젝트의 위치

- 화면 한 장 비교(GVT·GUIPilot)가 못 보는 **반응형·상태·디자인 시스템 결함**을 실제로 화면을 조작·측정해 찾는다.
- 원인 코드를 짚는다.
- 평가는 팀 프로젝트의 실제 수정 PR(결함 전·수정 커밋 쌍)로 한다.

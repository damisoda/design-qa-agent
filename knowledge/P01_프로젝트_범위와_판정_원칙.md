# P01 프로젝트 범위와 결함 판정 원칙

작성: 조대흠, 2026-10-06. 이 문서는 디자인-구현 결함 검수 에이전트가 무엇을 결함으로 보고 무엇을 보고하지 않는지 정한 프로젝트 기준이다.

## 에이전트가 하는 일

Figma 디자인(스냅샷)과 실행 중인 구현 화면을 비교해, 기준 화면에서는 맞아 보이지만 다음 상황에서 디자인과 어긋나는 결함을 찾는다.

1. 반응형: 화면 폭·높이가 바뀔 때, 키보드가 올라올 때, 기기 안전영역이 다를 때
2. 상태: 눌림(pressed)·비활성(disabled)·포커스(focus)·선택(selected) 상태일 때
3. 디자인 시스템: 디자인 토큰(색·글꼴·간격)과 컴포넌트를 써야 하는 곳

결함마다 디자인 기대값과 그 근거(Figma 속성), 측정값, 원인 코드(파일:줄), 수정 제안을 보고한다. 코드는 고치지 않는다.

## 판정 원칙

1. **수치는 측정에서만 나온다.** 폭·좌표·색·글꼴 크기는 브라우저 측정 도구의 출력만 인용한다. 코드를 읽고 계산한 값은 "추정"으로 표시하고 결함 판정에 쓰지 않는다.
2. **디자인 근거가 있어야 결함이다.** Figma에서 Fill container로 정의된 요소가 폭을 따라가지 않거나, 변형(variant)으로 정의된 상태가 구현에 없을 때처럼 디자인 속성으로 기대값을 말할 수 있어야 한다.
3. **디자인 의도가 모호하면 결함이 아니라 "사람 확인 필요"다.** 예를 들어 Figma가 375px 화면 하나만 정의했는데 320px에서 줄바꿈이 생긴 경우, 넘침·잘림·겹침처럼 명백히 깨진 것이 아니면 단정하지 않는다.
4. **명백히 깨진 것은 디자인 정의와 무관하게 결함이다.** 내용이 부모 밖으로 넘쳐 잘림, 글자가 다른 요소와 겹쳐 읽을 수 없음, 버튼이 탭바·키보드에 가려 누를 수 없음.
5. **보고 전에 같은 조건으로 다시 측정한다.** 다시 재현되지 않는 결함은 버리고 사유를 적는다.
6. **시안 전용 요소는 구분한다.** 상태바 시계(9:41), 홈 인디케이터 막대처럼 디자인 시안에만 있고 실제 기기가 그리는 요소를 앱이 그대로 그리면 "시안 잔재" 결함 후보로 본다.

## 결함으로 보지 않는 것

- 폰트 렌더링의 1~2px 차이, 안티앨리어싱 차이
- 실제 데이터 길이 차이로 생긴 줄 수 차이(디자인 견본 글자와 다른 경우). 단 잘림·겹침이 생기면 결함이다
- 디자인에 없는 기능을 구현에서 추가한 것(기능 범위 문제는 이 에이전트의 범위 밖)
- 백엔드 기능 오류, 성능 문제

## 측정 환경 기준

- 웹 빌드(react-native-web)를 모바일 뷰포트로 연다. 기본 크기는 375×812, 390×844, 430×932이고, 작은 기기 확인용으로 320×568을 쓴다.
- 데스크톱 브라우저와 헤드리스 브라우저에서는 안전영역(safe-area-inset-bottom)이 0이다. 실기기의 안전영역 차이는 별도로 표시한다.
- 실제 서버를 호출하지 않는 목 데이터 모드로 실행한다.

## 판정 결과의 종류

| 결과 | 뜻 |
|---|---|
| 결함 | 디자인 근거 또는 명백한 깨짐이 있고, 재측정에서도 재현됨 |
| 사람 확인 필요 | 디자인 의도가 모호하거나, 디자인 근거는 있으나 측정이 불완전함 |
| 결함 아님 | 측정값이 디자인 기대값과 허용 오차(2px) 안에서 같음 |
| 시험 못 함 | 화면·상태에 도달하지 못함. 이유를 적음 |

# dqa 시안 내보내기 (Figma 개발용 플러그인)

Figma에서 고른 화면 프레임을 dqa가 읽는 `design.json`(값)과 `design.png`(그림)로 내보낸다. 보내는 곳은 이 컴퓨터의 dqa 서버(`localhost:8792`)뿐이다. 외부 서버로는 보내지 않는다.

## 설치 (한 번)

1. Figma 데스크톱 앱을 연다. 웹 Figma에서는 개발용 플러그인을 가져올 수 없다.
2. 메뉴에서 Plugins → Development → Import plugin from manifest… 를 고른다.
3. 이 폴더의 `manifest.json`을 고른다.

## 쓰는 법

1. 터미널에서 dqa 서버를 켠다: `node dqa/cli.js serve` (주소 `http://127.0.0.1:8792`)
2. Figma에서 화면 프레임을 하나 이상 고른다. 프레임, 컴포넌트, 인스턴스를 고를 수 있다.
3. Plugins → Development → dqa 시안 내보내기 를 연다.
4. 묶음 이름을 넣는다(선택). 예: `신고 화면 v3`
5. 다음 둘 중 하나를 누른다.
   - **dqa로 보내기**: 시안 목록(`dqa/designs/<이름>/`)에 바로 들어간다.
   - **파일로 받기**: `<이름>.design.json`과 `<이름>.design.png`가 내려받아진다. 두 파일을 한 폴더에 `design.json`, `design.png`라는 이름으로 둔다.
6. 검사할 때 시안을 고른다.
   - 웹 화면: 새 검사 → 3단계 "Figma 시안과 비교"에서 고른다.
   - 명령: `node dqa/cli.js check --local <작업 폴더> --design <시안 이름>`
   - 화면이 여럿이면 `--design "local/home=홈-v3,local/detail=상세-v3"`처럼 화면마다 정한다.
   - 시안 목록 보기: `node dqa/cli.js design list`

## 내보내는 값

| 묶음 | 값 |
|---|---|
| 프레임 | 이름, 크기, 배경색 |
| 노드 위치 | 프레임 왼쪽 위 기준 x·y·w·h |
| 오토 레이아웃 | 방향, 간격, 안쪽 여백, 정렬, 줄바꿈 |
| 크기 방식 | Fill·Hug·Fixed (가로·세로) |
| 색 | 채움·테두리 색과 불투명도, 연결된 변수(토큰) 이름 |
| 모양 | 모서리 반경, 테두리 두께, 노드 불투명도 |
| 글자 | 내용, 글꼴, 크기, 굵기, 줄 높이(px), 자간(px), 색, 정렬, 자동 크기(한 줄 여부) |
| 그림 | 맞춤 방식(Fill·Fit·Crop·Tile) |
| 프로토타입 연결 | 누름 등 동작, 이동할 프레임 ID·이름, 목적지의 보이는 글자(실제 도착 화면과 비교) |

숨긴 노드는 빼고 내보낸다. 상태 표시줄과 홈 인디케이터는 비교할 때 dqa가 뺀다. 이름이 `Status Bar`, `Home Indicator`, `상태 표시줄`이어야 뺄 수 있다.

## 플러그인 없이 가져오기 (Figma REST)

개인 액세스 토큰(파일 읽기 권한)이 있으면 프레임 링크만으로 가져올 수 있다.

```bash
export FIGMA_TOKEN=...
node dqa/cli.js design pull --url "https://www.figma.com/design/<파일>/<이름>?node-id=12-34" --group "v3"
```

- 토큰은 환경 변수로만 읽는다. 파일에 적지 않는다.
- REST의 변수 API는 Enterprise 요금제에서만 쓸 수 있다. 그래서 REST로 가져올 때는 토큰 이름 대신 채움·글자 **스타일 이름**을 쓴다.
- 변수 이름까지 받으려면 플러그인을 쓴다.

목적지를 URL과 직접 연결하려면 내보낸 JSON의 `prototype_targets[프레임ID].route`에 구현 경로(예: `/checkout`)를 넣는다. 경로가 없으면 시작 화면과 겹치지 않는 목적지 글자로 확인한다. 목적지를 구별할 정보가 없으면 확인 불가로 기록한다.

## 확인 상태 (2026-10-14)

- 플러그인 코드는 가짜 figma 객체로 돌려 `design.json` 모양을 확인했다.
  - 오토 레이아웃, Fill, 변수 토큰, 프로토타입 연결, 상태 표시줄을 확인했다.
  - `/api/designs` 저장과 목록 조회도 확인했다.
- 실제 Figma 데스크톱에서 새 시안 3개를 선택해 실행했다. 좌표·글자·토큰·크기 방식·목적지 연결과 PNG가 로컬 시안 목록에 저장됐고, 그 실제 값으로 로컬 정상·오류·수정 프런트와 Dify를 검사했다. 결과: `eval/fresh-20261014/verification.json`.
- 실제 등록 과정에서 IP 형식 개발 허용 주소를 Figma가 거부해, 매니페스트와 UI 기본 주소를 공식 지원 형식인 `http://localhost:8792`로 맞췄다.
- REST 가져오기는 응답 모양을 본뜬 단위 시험만 통과했다. 실제 토큰으로 받아 본 적은 없다. **검증 필요.**

## 웹에서 앱 열기·요소 선택

`dqa serve`에서 **Figma 앱에서 시안 선택**을 누르고 이 플러그인을 실행한다. 실제 파일명과 선택한 프레임이 웹에 표시되면 **선택한 프레임 가져오기**로 가져온다. 검사 화면의 **Figma에서 이 요소 보기**는 동일 파일의 플러그인을 통해 해당 노드를 선택하고 확대한다. 연결은 로컬 `localhost:8792`만 사용한다. 일반 플러그인은 파일 키를 제공하지 않을 수 있으므로 링크와 파일의 일치를 추정하지 않는다.

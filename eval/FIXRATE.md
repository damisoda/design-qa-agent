# 수정 성공률 측정

dqa가 찾은 결함을 실제로 고치는지 잰다. 합성 앱에 결함을 하나씩 심고, 결함 변형마다 다음을 실행한다.

1. `dqa check`: 맞게 만든 구현(ok)을 비교 기준으로 주고, 심은 결함을 찾는지 본다.
2. `dqa fix`: 기본 모드(규칙 먼저, 모델 보조) 또는 `--mode model-only`로 고친다.
3. 오라클: 수정 패치를 결함 변형 사본에 적용하고, dqa 규칙과 따로 만든 `synth/verify_synth.js`로 정답 크기에서 결함이 사라졌는지 확인한다.

성공은 dqa 검증과 오라클을 모두 통과한 경우만 센다.

```bash
node eval/fixrate.js --tag dev --sets blind,blind2,blind3,blind4,blind5
node eval/fixrate.js --tag b7 --sets blind7 [--mode model-only] [--only id,id]
```

모델은 Gemma 4 E4B(Ollama, 생각 끔)다. 갈래 실행은 `DQA_BRANCHES=3`이다.

## 해석할 때 주의할 점

1. 블라인드 1~5는 결과를 보며 규칙을 고친 개발 세트라 `dev-r1`의 64%는 부풀려진 값이다.
2. 블라인드 7(`synth/make_blind7.py`, 앱 6종)은 개선 작업 전에 만들어 잠갔다(`synth/blind7/LOCK.txt`). 그러나 세트와 규칙 보강을 같은 작성자(Claude)가 만들었고, 잠근 뒤 `fix.js`가 한 번 바뀌었다. 그 사이 블라인드 7을 실행한 기록은 없다.
3. 합성 화면은 정적 HTML·CSS 한 장짜리다. 실제 서비스 코드에서의 성공률은 따로 재야 한다.
4. 갈래 실행은 실패 사례만 다시 돌린 것이고 각 1회라, 추가로 고친 2건은 우연일 수 있다.

# 블라인드 합성 예제 4묶음 (10-10)

블라인드 3에서 드러난 빈틈을 고쳤으므로, 블라인드 3은 개발용이 됐다. 고친 규칙의 일반화는 이 새 묶음으로 잰다. 규칙 파일을 고정한 채 한 번만 잰다.

## 측정 전에 정한 것

- 고정 기준: `cases.json`의 `frozen_rules_sha1`(`dqa/measure/inpage.js`와 `cluster.js` 내용의 해시, 55c647143372). 측정 직전에 같은 해시인지 확인했다.
- 채점: 블라인드 3까지와 같다. 단 R3(겹침)는 두 요소의 짝이므로, 보고된 요소 대신 상대 쪽 라벨에 힌트가 있어도 맞힌 것으로 센다. 측정 전에 정해 `grade_synth.js`에 넣었다.
- 화면 6종: 항공편 검색, 가계부, 배달 추적, 복약 알림, 배송지 입력 폼, 데스크톱 주간 일정. 앞선 24개 앱과 겹치지 않는다.
- 맞게 만든 화면에도 실제 앱에서 흔한 구성을 넣었다.
  - 가로 스크롤 날짜
  - 카드 위로 걸친 '최저가' 배지
  - 도넛 차트와 가운데 글자
  - 지도 위 칩
  - 단계 표시 선
  - 스위치
  - 입력칸 옆 버튼과 입력칸 안 지우기 버튼
  - 반으로 나눠 나란히 놓은 겹친 일정
  - 끈끈한 요일 머리글
- 결함 36개
  - 바이브코딩에서 흔한 실수에서 골랐다.
  - 규칙 범위(R1~R7, A1, A2, D4) 30개, 규칙 밖 6개(색 토큰 2, 글자 굵기, 선택 상태, 크기 방식, 정렬)
  - dqa가 아직 보지 않는 종류도 일부러 넣었다.
    - SVG 위 글자(도넛 가운데)
    - 한 요소 안 줄끼리의 겹침(줄 높이 실수)
    - 입력칸 안내 글자(placeholder) 대비
    - 투명도(opacity)로 흐린 글자
    - 그림 위 반투명 칩
- 정답: `verify_synth.js --set blind4`(dqa 규칙과 따로 만든 선택자 측정)로 확인했다.
  - 이 묶음을 위해 측정 네 가지를 더했다.
    - 원 안쪽에 글자가 드는지(`text_in_circle`)
    - 줄끼리 겹침(`line_overlap`)
    - 안내 글자 대비(`contrast_placeholder`)
    - 투명도를 반영한 대비(`contrast_opacity`)
  - "닿을 수 없음" 측정은 더 가까운 스크롤 영역이 있으면 닿는 것으로 고쳤다.
  - 처음에 4개가 결함을 만들지 못했다. 가게 이름이 짧았고, 입력칸이 자기 최소 폭까지 줄었고, 겹친 일정에서 덮이는 쪽을 잘못 골랐다. 측정 하나는 맞게 만든 화면을 결함으로 셌다. dqa를 돌리기 전에 고쳤다.
  - 36개 모두 정답 크기가 있고, 맞게 만든 화면 6개는 모두 깨끗하다.
- 결과를 본 뒤 규칙을 고치면 이 묶음도 개발용이 된다.

못 맞힌 6개의 원인은 아래와 같다. 측정 뒤 결과와 코드 조건으로 확인했고, 규칙은 고치지 않았다.

| 결함 | 원인 |
|---|---|
| 항공사 로고가 24×24 칸에서 찌그러짐(D4) | D4는 넓이 900px²(30×30) 미만인 그림을 건너뛴다. 작은 아이콘·로고의 왜곡을 보지 않는다 |
| 도넛 가운데 글자가 링 위로 넘침(R3) | 겹침 상대로 SVG 도형을 보지 않는다 |
| 지도 위 반투명 칩의 옅은 글자(A2) | 그림 위 글자는 그림 픽셀로 재는데, 글자 쪽에 반투명 배경이 있으면 "읽기를 챙긴 것"으로 보고 건너뛴다. 칩 배경을 그림 픽셀에 섞어 재지 않는다 |
| 약 이름의 줄끼리 겹침(R3, 줄 높이 10px) | 겹침은 서로 다른 요소끼리만 본다. 한 요소 안 줄끼리는 보지 않는다 |
| 입력칸 안내 글자(placeholder) 대비 1.6:1(A2) | 안내 글자(::placeholder)는 글자 노드가 아니라 검사하지 않는다 |
| 지난 일정을 투명도 40%로 흐림(A2) | 대비 계산이 opacity를 반영하지 않는다 |

맞게 만든 화면의 보고 4건
- 위아래로 쌓은 요일 버튼·머리글('월' 위, '13' 아래)을 짧은 라벨이 두 줄로 꺾였다고 셌다(R6, 복약·일정 2건).
  - 블라인드 3 뒤에 검사 대상을 "글자를 직접 품은 모든 요소"로 넓히면서 생겼다.
  - 이제 '월'과 자식 `<b>13</b>`를 품은 버튼 전체를 한 라벨로 보기 때문이다. 자식이 일부러 다른 줄에 놓인 경우를 가리지 못한다.
- 판단 보류: 태블릿 폭(768)에서 반으로 나눈 일정 칸(65px)이 시간 글자를 잘랐다(R2).
  - 일정 칸이 글자를 자르는 것은 캘린더에서 흔하다.
  - 다만 이 경우 줄이 반쯤 잘려 획이 끊겨 보이므로 진짜 결함으로 볼 여지도 있다.
- 같은 화면 768 폭에서 일정 제목이 1줄에서 2줄이 된 것을 크기별 차이(R5)로 셌다. 좁은 칸에서의 줄바꿈은 정상이다.

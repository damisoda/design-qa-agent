# 블라인드 합성 예제 2묶음 (10-10)

블라인드 1에서 드러난 빈틈 6가지를 고쳤으므로, 블라인드 1은 개발용이 됐다. 고친 규칙의 일반화는 이 새 묶음으로 잰다. 규칙 파일을 고정한 채 한 번만 잰다.

## 측정 전에 정한 것

- 고정 기준
  - `cases.json`의 `frozen_rules_sha1`: `dqa/measure/inpage.js`와 `cluster.js` 내용의 해시
  - 측정 직전에 같은 해시인지 확인한다. 커밋 전에도 고정 상태를 확인할 수 있게 해시로 적는다.
- 화면 6종: 음악 플레이어, 운동 기록, 뉴스 기사, 설문 온보딩, 마이페이지, 데스크톱 메일함. 앞선 12개 앱(개발용 6, 블라인드 1의 6)과 겹치지 않는다.
- 결함 34개
  - 바이브코딩에서 흔한 실수에서 골랐다. 시안 값을 고정 px로 옮김, 절대 위치로 맞춤, 말줄임·줄바꿈 처리를 뺌, 여백을 지움 같은 것이다.
  - 규칙 범위(R1~R7, A1, A2, D4) 27개, 규칙 밖 7개
  - 규칙 밖은 색 토큰 D2, 간격 L2, 글자 굵기 D3, 크기 방식 F1, 선택 상태 S4, 정렬 L1 2개다.
  - dqa가 잡기 어려울 것으로 보이는 결함도 일부러 빼지 않았다.
    - 사진 위로 올라간 사진 설명(그림은 겹침 상자 후보가 아니다)
    - 화면 맨 위가 아닌 곳에 고정된 탭이 첫 내용을 가림
    - 큰 영역 안의 잘림
- 정답: `verify_synth.js --set blind2`(dqa 규칙과 따로 만든 선택자 측정)로 확인했다.
  - 결함 변형에서 결함이 있고 맞게 만든 화면에서 같은 측정이 깨끗한 크기만 정답으로 넣었다.
  - 처음에 2개가 결함을 만들지 못했다. 그래프 그림은 다른 CSS가 폭을 100%로 덮어썼고, 메일 제목은 너무 짧았다. dqa를 돌리기 전에 고쳤다.
  - 34개 모두 정답 크기가 있고, 맞게 만든 화면 6개는 모두 깨끗하다.
- 채점(`grade_synth.js --set blind2`)은 블라인드 1과 같다. 결함 유형 코드가 같고, 보고된 요소의 라벨에 글자 힌트 하나가 들어 있으며, 정답 크기에서 나왔을 때만 맞힌 것으로 센다.
- 결과를 본 뒤 규칙을 고치면 이 묶음도 개발용이 된다.

## 결론

- 블라인드 1의 빈틈 6가지를 고친 뒤에도 처음 보는 앱에서의 탐지는 81%로 블라인드 1(81%)과 같았다.
  - 이번 묶음에서 고친 빈틈(큰 시트, 바닥글, 여러 줄 글자, FAB, 상자 겹침, 카드 겹침)과 같은 종류로 놓친 것은 없었다.
  - 대신 새 앱이 새 빈틈을 드러냈다. 빠진 태그(`time`), 불투명 배지 예외, 그림 위 글자, 머리글 아래 고정 막대다.
- 규칙 기반 탐지는 앱 묶음마다 새 빈틈이 나오는 구조다. 고칠 때마다 개발용 수치는 오르지만, 일반화는 새 묶음으로만 확인할 수 있다.
- 빠진 태그 같은 빈틈은 "글자를 직접 품은 모든 요소"를 후보로 보도록 바꾸면 종류째 없앨 수 있다. 다음 수정 후보다.
- 규칙 밖 7종은 하나도 못 잡는다. 시안 명세(design.json)와 구현을 비교하는 기능이 있어야 한다. 이 묶음의 화면마다 design.json이 있으므로 그 기능의 시험에 쓸 수 있다.
- 이 결과를 보고 규칙을 고치면 이 묶음도 개발용이 된다.

## 빈틈을 고친 뒤 (10-10, 이 묶음은 이제 개발용)

위 결과를 보고 규칙을 고쳤으므로, 이 묶음은 더 이상 일반화를 말해 주지 않는다. 고친 규칙의 일반화는 `../blind3/`에서 다시 잰다.

| 빈틈 | 고친 것(`dqa/measure/inpage.js`) |
|---|---|
| `<time>` 안 글자(R6) | 검사 대상을 태그 목록 대신 "글자를 직접 품은 모든 요소"로 바꿨다. 아이콘과 글자가 섞인 버튼의 글자, `<p>총 <b>3</b>건</p>`의 바깥 글자도 대상이 된다. 섞인 요소는 자기 글자 노드만 잰다 |
| 불투명 배지가 글자를 덮음(R3, 2건) | 덮어 가린 것으로 보는 불투명 층을 화면의 15%보다 큰 것(시트·카드·메뉴)으로 좁혔다. 작은 배지·칩이 글자를 덮으면 겹침이다 |
| 사진 설명이 사진 위로 올라감(R3) | 글자가 `<img>` 위에 그려지면 그림 픽셀을 읽어 대비를 잰다. 흐름 속 글자가 그림 위로 밀려 대비가 3:1 미만이면 R3, 일부러 얹은(절대 위치) 글자가 4.5:1(큰 글자 3:1) 미만이면 A2다. 글자 쪽 배경·반투명 막·글자 그림자가 있으면 뺀다 |
| 머리글 아래 고정 탭이 첫 내용을 가림(R4) | 화면 위 20% 안에 걸친 넓은(화면 폭 80% 이상) 고정 막대도 위쪽 덮개로 본다 |
| 잠깐 뜨는 알림 오탐 2건(R3) | 위치를 띄운 `role=status`·`alert`·`aria-live` 영역이 덮는 것은 겹침에서 뺀다. 누를 요소를 덮으면 R4로 본다 |

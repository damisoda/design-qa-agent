# 블라인드 합성 예제 (10-10)

규칙을 고친 합성 예제(개발용, `../`)는 일반화 성능을 말해 주지 않는다. 그래서 dqa 규칙을 커밋 3fae9f3으로 고정한 채 새 앱 6종에 결함 30개를 심고, 한 번만 잰다.

## 측정 전에 정한 것

- 화면: 로그인, SNS 피드, 지도 검색, 예약 캘린더, 결제 영수증, 데스크톱 랜딩. 앞선 예제와 겹치지 않는다.
- 결함은 dqa 규칙 목록에서 고르지 않고, 바이브코딩에서 흔한 결함에서 골랐다. 규칙이 아직 없는 종류도 4개 섞었다.
  - S3 포커스 표시 없음
  - D3 글자 굵기 불일치
  - F1 Fill이어야 할 폭이 고정됨
  - L1 정렬 어긋남
- 정답: `verify_synth.js --set blind`로 확인했다. 결함 변형에서 결함이 있고, 맞게 만든 화면에서 같은 측정이 깨끗한 크기만 정답으로 넣었다. 결함 30개 모두 정답 크기가 있고, 맞게 만든 화면 6개는 모두 깨끗하다.
  - 심는 방법은 dqa를 돌리기 전에 고쳤다. 처음에 13개가 결함을 만들지 못했기 때문이다(한국어 줄바꿈, margin collapse, 1fr 칸이 늘어남 등).
- 채점(`grade_synth.js --set blind`)
  - 규칙 범위(R1~R7, A1, A2, D4) 결함의 탐지 여부와 크기별 탐지
  - 규칙 밖 결함의 탐지 여부
  - 맞게 만든 화면의 보고 수(오탐)
  - 결함 화면의 추가 보고 수
- 탐지 기준: 결함 유형 코드가 같고, 보고된 요소의 라벨에 글자 힌트 하나가 들어 있으며, 정답 크기에서 나왔을 때만 맞힌 것으로 센다.
- 결과를 본 뒤 규칙을 고치면, 이 묶음은 개발용이 된다. 그 경우 일반화는 다시 새 묶음으로 잰다.

## 결과 (10-10, 한 번만 잼, LLM 끔, `../../results/blind1.json`)

| | 값 |
|---|---|
| 규칙 범위 결함 26개 탐지(미리 정한 채점 그대로) | **21개(81%)**, 크기별 84% |
| 규칙 밖 결함 4개(포커스·굵기·Fill·정렬) | 0개 |
| 맞게 만든 화면 6개의 보고 | 4건: 진짜 결함 1, 오탐 3 |
| 결함 화면의 추가 보고 | 26건(대부분 같은 원인의 다른 요소) |

못 맞힌 5개를 하나씩 보면 이렇다.

| 결함 | dqa가 한 것 | 원인 |
|---|---|---|
| 영수증 제목과 '결제 완료' 배지 겹침(R3) | R3로 정확히 보고했다 | 채점 실수. 정답의 글자 힌트("결제가 완료")가 심을 때 바꾼 제목("결제가 정상적으로 완료되었어요")과 안 맞았다. 힌트를 고치면 22/26(85%)이다 |
| 지도 핀 이름과 지도 버튼 겹침(R3) | 같은 핀 이름을 R4(아래 시트에 4px 가려짐)로 보고했다 | 요소는 맞혔지만 유형이 다르다. 핀 이름과 버튼의 겹침은 잡지 못했다(원인 검증 필요) |
| 기능 카드끼리 겹침(R3) | 같은 카드 글자를 R1(화면 밖으로 36px)로 보고했다 | 요소는 맞혔지만 유형이 다르다. 카드 상자끼리의 겹침은 글자와 상자 겹침으로 잡히지 않았다 |
| 아래 시트가 60%로 커져 지도 버튼을 가림(R4) | 보고 없음 | R4는 화면의 40%보다 큰 덮개를 뒤에 깔린 화면으로 보고 뺀다. 큰 시트가 이 조건에 걸렸다 |
| 바닥글 글자 대비 2.4:1(A2) | 보고 없음 | 글자가 `<footer>` 안에 바로 있어 검사 대상 태그 목록에 없었다 |

맞게 만든 화면의 보고 4건은 이렇다.
- 진짜 결함 1건: 로그인 화면 320×568에서 '로그인' 버튼이 52px가 아니라 22px로 눌려 그려진다. 스크롤 영역 안의 flex 항목이 줄어든 것으로, 심지 않은 결함을 dqa가 찾았다(캡처로 확인).
- 오탐 3건
  - 여러 줄에 걸친 긴 해시태그의 바깥 상자 안에 다음 해시태그가 들어간 것을 겹침으로 셌다. 글자 영역을 줄 단위로 재지 않고 한 상자로 잰 탓이다.
  - 떠 있는 글쓰기 버튼(FAB) 아래로 스크롤 내용이 지나가는 것을 겹침으로 2건 셌다.

## 결론

- 처음 보는 앱과 결함에서 규칙 범위 결함의 81%(채점 실수를 고치면 85%)를 정답 크기에서 잡았다. 요소는 맞히고 유형만 다른 2건까지 넣으면 26개 중 24개다.
- 개발용 합성 예제의 100%보다 낮은 것이 일반화의 실제 모습이다.
- 규칙 밖 4종(상태·디자인 값·크기 방식·정렬)은 하나도 못 잡는다. 상태 검사와 Figma 비교(design.json과 대조)가 있어야 한다.
- 이 결과를 보고 규칙을 고치면 이 묶음은 개발용이 된다. 고친 뒤의 일반화는 새 블라인드 묶음으로 다시 잰다.

## 빈틈을 고친 뒤 (10-10, 이 묶음은 이제 개발용)

위 결과를 보고 규칙을 고쳤으므로, 이 묶음은 더 이상 일반화를 말해 주지 않는다. 고친 규칙의 일반화는 `../blind2/`에서 다시 잰다.

| 빈틈 | 고친 것(`dqa/measure/inpage.js`) |
|---|---|
| 큰 아래 시트가 지도 버튼을 가림(R4) | 화면의 40%보다 큰 덮개도, 아래에 붙은 시트가 누를 요소를 덮으면 본다. 모달 대화상자와 화면 전체를 덮는 층은 뺀다 |
| `<footer>` 안 글자(A2) | 검사 대상 태그에 footer, header, nav, section, article, aside, main, address, blockquote를 넣었다 |
| 여러 줄 해시태그 오탐(R3) | 글자 겹침을 바깥 상자 하나가 아니라 줄마다의 사각형으로 잰다 |
| 떠 있는 글쓰기 버튼 아래 스크롤 내용 오탐(R3) | 스크롤되는 내용과 그 스크롤 밖의 떠 있는 층(FAB 등)의 겹침은 R3에서 빼고, 스크롤 끝에서도 가리면 R4로 본다 |
| 지도 핀 이름과 지도 버튼 겹침 놓침(R3) | 원인: 글자 획은 1px만 닿고 핀 칩 상자가 버튼과 27×3px 겹쳤다. 글자를 품은 칩·카드·버튼 상자끼리의 겹침을 더했다(아이콘 위 배지, 시트·대화상자 아래, 떠 있는 층 아래는 뺀다) |
| 카드끼리 겹침을 R1으로만 보고(R3) | 원인: "글자 쪽 층이 덮으면 겹침 아님" 예외가 위아래를 보지 않았다. 겹친 지점의 맨 위가 상대 상자면 예외를 쓰지 않는다 |

채점 실수 1건(영수증 제목 힌트)도 고쳤다(`cases.json`의 `hint_note`).

| | 처음(규칙 3fae9f3) | 고친 뒤 |
|---|---|---|
| 규칙 범위 결함 26개 탐지 | 21개(81%) | 26개(100%), 크기별 99% |
| 맞게 만든 화면의 보고 | 4건(진짜 1, 오탐 3) | 1건(진짜 결함: 320×568 로그인 버튼 눌림) |
| 규칙 밖 4종 | 0개 | 0개 |

같은 규칙으로 돌린 회귀 시험
- 개발용 합성 예제: 23/23, 맞게 만든 화면 0건(`../../results/synth3-gaps.json`)
- 팀 앱 개발 사례 #168·#217·#221: 4/4, 수정 후 남음 0(`../../results/dev-b2-rules3.json`)
  - 수정 전 그 밖 보고는 화면당 4.7건에서 5.0건으로 늘었다. 늘어난 1건은 #221 수정 전의 입력칸끼리 겹침으로, 알려진 결함의 증상이다.
  - 처음 고친 판에서는 #217의 가족 선택 시트가 뒤 화면을 덮은 것을 상자 겹침으로 세는 오탐 2건이 나왔다. 대화상자·큰 고정 층 예외를 더해 없앴다.

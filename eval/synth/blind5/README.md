# 블라인드 합성 예제 5묶음 (10-10 측정, 10-12 정리)

블라인드 4에서 드러난 빈틈을 고친 뒤의 일반화를 잰다. 규칙 파일을 고정한 채 한 번만 쟀다.

## 측정 전에 정한 것

- 고정 기준: `cases.json`의 `frozen_rules_sha1`(aa0244a9c1a7). 측정 직전에 같은 해시인지 확인했다.
- 채점: 블라인드 4와 같다(R3는 짝 기준).
- 화면 6종: 영화 좌석 선택, 커뮤니티 글, 스마트홈, 주식 포트폴리오, 온라인 퀴즈, 데스크톱 노트 편집기. 앞선 30개 앱과 겹치지 않는다.
- 맞게 만든 화면에 넣은 흔한 구성
  - 좌석 격자와 화면 막대
  - 글 속 링크가 섞인 본문, 대댓글 들여쓰기
  - 그라데이션 카드, SVG 다이얼
  - 차트 말풍선과 축 글자
  - 코드 블록 가로 스크롤, 도구 막대 가로 스크롤
  - 화면 폭에 따라 숨는 댓글 패널
- 결함 38개: 규칙 범위 32개, 규칙 밖 6개(색 토큰 2, 선택 상태 2, 정렬, 간격)
- 정답: `verify_synth.js --set blind5`로 확인했다.
  - 처음에 1개(수익률 칸 폭이 글자보다 넓음)가 결함을 만들지 못했다.
  - 측정 1개(코드 블록의 의도된 가로 스크롤을 넘침으로 셈)는 맞게 만든 화면을 결함으로 셌다.
  - 둘 다 dqa를 돌리기 전에 고쳤다. 38개 모두 정답 크기가 있고, 맞게 만든 화면은 모두 깨끗하다.
- 맞게 만든 노트 화면에 있던 진짜 결함 하나는 고치지 않고 그대로 뒀다. 36px 서식 버튼 안에서 '할 일'이 두 줄로 꺾인다. 앞선 묶음의 로그인·재생목록 버튼과 같은 방식이다.

## 결과 (10-10, 한 번만 잼, LLM 끔, `../../results/blind5.json`)

| | 값 |
|---|---|
| 규칙 범위 결함 32개 탐지 | **31개(97%)**, 크기별 95% |
| 규칙 밖 결함 6개 | 0개 |
| 맞게 만든 화면 6개의 보고 | 4건(모두 노트 화면): 진짜 결함 1, 판단 보류 3 |
| 결함 화면의 추가 보고 | 33건(대부분 노트 화면의 같은 4건이 변형마다 되풀이됨, 나머지는 같은 결함의 증상) |

못 맞힌 1개
- 그라데이션 온도 카드의 흰 글자(A2): A2는 배경이 그라데이션·그림(background-image)이면 건너뛴다. 그라데이션 색을 섞어 재지 않는다.

맞게 만든 화면의 보고 4건
- 진짜 결함 1건: 36px 서식 버튼 안에서 '할 일'이 두 줄로 꺾인다(R6).
- 판단 보류 3건: 할 일 목록의 체크박스(18px)를 감싼 label 높이가 22px라 24px 기준에 못 미친다(A1).
  - dqa 기준(누를 영역 24px)으로는 맞다.
  - WCAG 2.2의 간격 예외(24px 원이 다른 누를 곳과 안 겹치면 통과)를 적용하면 통과한다.

결함 화면의 추가 보고 중 진짜 증상
- 선택 좌석 색을 #EF4444로 바꾸자 흰 좌석 번호의 대비가 3.76:1로 떨어졌다(A2).
- 수익 색을 #EF4444로 바꾸자 수익 글자 대비가 3.76:1이 됐다(A2).
- 시안 좌표에 고정한 댓글 패널이 1024 폭에서 화면 밖으로 나갔다(R1).

측정 시간
- 이 묶음을 잴 때 일부 실행이 20~60초 걸렸다(평소 4~7초).
- 10-12에 같은 화면을 다시 재니 4.9초였다(당시 43초). 측정 당시의 일시적인 기기 부하로 보인다.

## 결론

| 묶음 | 규칙 범위 탐지 | 맞게 만든 화면 보고 |
|---|---|---|
| 블라인드 1 | 81% | 오탐 3 |
| 블라인드 2 | 81% | 오탐 2 |
| 블라인드 3 | 84% | 오탐 1 |
| 블라인드 4 | 80% | 오탐 3, 판단 보류 1 |
| 블라인드 5 | **97%** | 진짜 1, 판단 보류 3, 오탐 0 |

- 처음으로 80%대를 넘었다. 다만 이 묶음의 결함 종류가 앞선 묶음과 많이 겹친다. 넘침·잘림·대비·누를 영역은 이제 흔한 실수를 대부분 잡는다.
- 남은 규칙 범위 빈틈은 그라데이션·배경 그림 위 글자 대비다.
- 규칙 밖 6종(색 토큰, 선택 상태, 정렬, 간격)은 다섯 묶음 모두에서 0이다. 다음 단계는 시안(design.json)과 구현의 값을 직접 비교하는 기능이다.

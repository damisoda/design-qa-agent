# 블라인드 합성 예제 3묶음 (10-10)

블라인드 2에서 드러난 빈틈 5가지를 고쳤으므로, 블라인드 2는 개발용이 됐다. 고친 규칙의 일반화는 이 새 묶음으로 잰다. 규칙 파일을 고정한 채 한 번만 잰다.

## 측정 전에 정한 것

- 고정 기준: `cases.json`의 `frozen_rules_sha1`(`dqa/measure/inpage.js`와 `cluster.js` 내용의 해시, cbbfdafa6ebc). 측정 직전에 같은 해시인지 확인했다.
- 화면 6종: 레시피, 할 일, 동영상 강의, 부동산 매물, 날씨, 데스크톱 칸반. 앞선 18개 앱과 겹치지 않는다.
  - 레시피는 태블릿 폭(768×1024)도 잰다. 폰 크기 앱 틀(430)이 가운데에 놓이는 경우다.
  - 매물의 안전영역 결함은 노치 기기 크기(47/34, 59/34)에서만 잰다.
- 맞게 만든 화면에도 실제 앱에서 흔한 구성을 일부러 넣었다. 오탐이 나기 쉬운 구성이다.
  - 그림 위에 얹은 글자와 버튼(재생 버튼, 강의 이름, 사진 수, 재생 시간)
  - 겹쳐 쌓은 아바타
  - 가로 스크롤 줄
  - 열린 드롭다운 메뉴
  - 아이콘이 섞인 버튼
  - 반투명 카드
  - 떠 있는 타이머 막대
- 결함 38개
  - 바이브코딩에서 흔한 실수에서 골랐다. 시안 좌표를 절대 위치로 박음, 고정 px 폭, 넘침 숨김, 음수 여백, 경로 실수, 반투명 막 제거, 안전영역 누락, 화면 기준 고정 같은 것이다.
  - 규칙 범위(R1~R7, A1, A2, D4) 32개, 규칙 밖 6개(크기 방식 F1, 정렬 L1 2, 글자 크기 D3, 간격 L2, 모서리 D5)
- 정답: `verify_synth.js --set blind3`(dqa 규칙과 따로 만든 선택자 측정)로 확인했다.
  - 이 묶음을 위해 측정 두 가지를 더했다. 앱 틀 이탈(`frame_escape`)과 그림 위 글자 대비(`contrast_img`, 그림 픽셀을 직접 읽음)다.
  - 측정 옵션 두 가지도 더했다. label이 감싼 입력칸은 label 전체를 누를 곳으로 보고, 일부러 가로 스크롤하는 줄은 넘침으로 보지 않는다.
  - 처음에 6개가 결함을 만들지 못했다. 글자가 짧았거나, 머리글 오른쪽 여백이 넘침을 흡수했거나, 절대 위치 마감 시각이 제목이 아니라 배지 위에 놓였기 때문이다. 정답 측정 2개도 맞게 만든 화면을 결함으로 셌다. dqa를 돌리기 전에 고쳤다.
  - 38개 모두 정답 크기가 있고, 맞게 만든 화면 6개는 모두 깨끗하다.
- 채점(`grade_synth.js --set blind3`)은 블라인드 1·2와 같다. 결함 유형 코드가 같고, 보고된 요소의 라벨에 글자 힌트 하나가 들어 있으며, 정답 크기에서 나왔을 때만 맞힌 것으로 센다.
- 결과를 본 뒤 규칙을 고치면 이 묶음도 개발용이 된다.

| 규칙 밖 결함 6개(크기 방식·정렬 2·글자 크기·간격·모서리) | 0개 |

- 맞게 만든 화면에 일부러 넣은 구성에서는 오탐이 나지 않았다. 그림 위 글자와 버튼, 겹쳐 쌓은 아바타, 가로 스크롤, 열린 메뉴, 아이콘이 섞인 버튼, 떠 있는 타이머다.

못 맞힌 5개는 아래와 같다. 원인은 측정 뒤 디버그 스캔으로 확인했고, 규칙은 고치지 않았다.

| 결함 | dqa가 한 것 | 원인 |
|---|---|---|
| 타이머 막대가 태블릿 폭에서 앱 틀 밖으로 늘어남(R7) | 768×1024에서 같은 막대 안 '일시정지'를 R1(앱 틀 오른쪽 밖)로 보고 | R7은 높이 60px 이상인 고정 요소만 후보로 본다. 타이머는 48px다. 요소와 크기는 맞았고 유형만 다르다 |
| 단계 설명 글자가 번호 원 위에 겹침(R3) | R3로 보고했지만 보고된 요소가 번호 원('1'~'4')이고 설명 글자는 상대 쪽에 적힘 | 겹친 짝은 맞혔다. 채점이 보고된 요소의 라벨만 보고, 힌트를 설명 글자로만 정해서 놓친 것으로 셌다. 짝의 양쪽을 보는 채점이면 28/32다 |
| 자료 받기 아이콘 링크가 18px(A1) | 보고 없음 | A1은 "글 속 링크"를 빼려고, 부모 글자가 링크 글자보다 길면 뺀다. 글자 없는 아이콘 링크에도 이 예외가 걸렸다 |
| 사진 위 뒤로·공유 버튼이 노치 아래로 들어감(R4) | 보고 없음 | 안전영역 검사는 글자를 품은 요소만 본다. 아이콘만 있는 버튼(svg)은 검사하지 않는다 |
| 반투명 카드 위 최저 기온 글자 대비 3.3:1(A2) | 보고 없음 | A2는 배경이 반투명(이 카드는 흰색 10%)이면 건너뛴다. 아래 배경과 섞은 색을 계산하지 않는다 |

오탐 원인 3가지
- 큰 숫자의 글자 영역: 날씨의 '18°'(88px, 줄 높이 96px)는 글자 영역(Range)이 줄 상자보다 위아래로 4px 크다. 그래서 바로 아래 줄과 3px 겹친다고 셌다. 실제 획은 닿지 않는다. 맞게 만든 화면 1건과, 날씨 결함 화면마다 같은 보고가 1건씩 나왔다.
- 스크롤 영역 밖의 얇은 막대: 강의 화면 375×667의 한 스크롤 위치에서, 스크롤 영역 위로 밀려나 안 보이는 재생 진행 막대가 위 머리글 '강의'와 겹친다고 셌다. 얇은 막대 검사가 막대를 스크롤 영역으로 잘라 보지 않는다.
- 자기 자신이 숨긴 줄: 강의 설명(최대 높이와 넘침 숨김)의 숨겨진 셋째 줄이 아래 자료 상자와 겹친다고 셌다. 겹침 계산이 조상의 넘침 숨김만 보고 자기 자신의 넘침 숨김은 보지 않는다.
